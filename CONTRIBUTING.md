# Contributing to 0xVerse Cohort Capstone

All work starts with a GitHub Issue. Ask a mentor to clarify acceptance criteria before coding.

## Workflow

1. Assign or accept an Issue.
2. Update local `main` with `git pull --ff-only`.
3. Create `feature/<student-or-team>/<task>` or `fix/<area>/<task>`.
4. Commit focused changes using clear imperative messages.
5. Push the branch and open a pull request with `gh pr create`.
6. Link the Issue with `Closes #<number>` and complete the pull request checklist.
7. Respond to review comments; do not resolve substantive mentor comments without addressing them.
8. A mentor merges after approval and successful checks.

Never push directly to `main`, force-push a shared branch, or commit credentials, tokens, private keys, `.env` files, or personal data.

## Review expectations

- Keep the pull request scoped to one Issue.
- Add or update tests where appropriate.
- Document behavior and setup changes.
- Include screenshots for UI changes.
- Be respectful, specific, and evidence-based in reviews.
